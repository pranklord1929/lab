### CODEX-2 — panne reproductible (critique)

Capture tmux :

```text
Réponds exactement: FIX_CODEX2
thediningdispatch@Mac codex-2 % Réponds exactement: FIX_CODEX2
zsh: command not found: Réponds
… FIX_CODEX2_RETRY / AUDIT3_C2 → même pattern
```

**Chaîne :**

1. `codex` a quitté ; il reste un **zsh**  
2. CHAT / send-probe collent le prompt dans le shell  
3. zsh exécute `Réponds` → *command not found*  
4. Engine : `submitting` → `failed` (timeout 12 s), réponse vide  
5. L’UI / le probe croient encore `@agent_provider=openai` + un vieux JSONL (`CODEX2_OK`)

**Manque produit :** badge « process exited », refus de submit, ou respawn automatique.

### Chemin sain (display CHAT + transport)

- **CODEX-1 / GROK-1 / GROK-2** : `submitting → running → completed`, réponse exacte dans le transcript et donc dans ce que le CHAT afficherait.  
- **2ᵉ tour Grok-2** : **OK** ce matin (`AUDIT3_G2` puis `AUDIT3_G2B`) — le flaky « draft Enter:send » n’a pas rejoué sur ces deux envois (mitigations WIP `sendLine` probablement en cause).

### Claude

- Historique probe : `[blocked]` quota mensuel correctement classé.  
- Nouveau submit : **failed** (pas d’ack dans le JSONL) ; terminal parfois marqué busy.  
- Capture native souvent peu lisible / vide côté TERM.

## Chemin vers une version « optimisée non buggée » (recommandations, sans code)

Ordre de travail suggéré pour **un autre agent / une session fix** :

1. **Cycle de vie process** — détecter `pane_current_command` / absence d’enfants CLI ; bloquer CHAT + afficher l’état ; option respawn.  
2. **Durcir launch / respawn** — garantir que le CLI reste up (CODEX-2 meurt encore).  
3. **Commit / revue du WIP** déjà dans le tree (C2, Claude stop, locator, queue, sendLine) + faire passer les tests.  
4. **Doctor** = santé process, pas seulement présence de pane.  
5. **Transport** — remplacer sleeps par ack transcript uniquement (déjà partiel) + message UI « encore dans le composer ».  
6. **Layout** — recreate pane doit restaurer la mosaïque 3×2, pas un split orphelin.  
7. Nettoyer confs d’exemple / working tree pour un ship propre.
